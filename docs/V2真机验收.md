# V2 真机验收

本文是 V2 的验收门禁和现场记录模板，不是自动执行脚本。本轮仅整理文档与资源，
**没有连接、读取或驱动真实硬件，也不能据此声称真机验收已经完成。**

## 1. 验收基线

- 当前 `robot.variant` 必须是 `V2`，权威 profile 为 `配置/robot_v2.yaml`。
- URDF 必须是 `URDF运动学仿真/urdf/v2/soarmoce_urdf.urdf`，TCP 为 `Link_7`。
- V2 mesh 必须来自 `URDF运动学仿真/meshes/v2/`。
- 受版本控制的 `真实舵机控制/真实配置.yaml` 必须保持串口为空、`dry_run: true`。
- 实际串口只放在被忽略的 `真实配置.local.yaml` 或环境变量 `ARM_ROBOT_PORT`。
- 实际标定只放在被忽略的 `真实舵机控制/标定/current.local.json`。
- `标定/v1.example.json` 与 `标定/v2.example.json` 只是模板，绝不能用于真机。

配置加载顺序为：受控基础配置 → 被忽略的本地覆盖 → 权威型号 profile → 运行参数
环境变量。型号由受控基线或 `真实配置.local.yaml` 的 `robot.variant` 选择；环境变量
不提供型号选择，只覆盖串口、驱动后端和 `dry_run`。profile 决定关节、传动、限位与
raw 可达关节等硬件字段，本地文件不能覆盖它们。

## 2. 离线检查

以下命令只用于仿真或静态检查：

```bash
mamba run -n momo_rebot python URDF运动学仿真/URDF检查_urdf_inspector.py
mamba run -n momo_rebot python 真实舵机控制/V2真机验收_v2_acceptance.py
```

报告必须明确 `hardware_writes: false`。标定文件必须是
`_meta.robot_variant: V2`，动作文件必须是顶层 `robot_variant: V2`；对应字段缺失、
未知或与当前型号不匹配时，只能仿真或 `dry_run` 预览。

V2 的 `raw_reachable_joints` 是 `j12`、`j13`。两轴的有效逻辑范围必须由本次验收
读取到的 Home、传动映射和绝对 raw 上限 `±30719` 动态计算。静态配置限位不能替代
该范围，任何入口都不得绕过它。

## 3. 现场审批门

下面每一项都是独立阶段。操作人员必须在进入该阶段前取得单独、明确的批准；上一个
阶段的批准不能自动延续到下一个阶段。任一异常立即停止，不得跳过或合并阶段。

| 阶段 | 允许的最小操作 | 通过条件 |
|---|---|---|
| 1. ping | 仅确认目标总线设备在线 | ID、端口和型号与记录一致 |
| 2. 只读 raw | 只读位置、温度、电压和状态 | 无写入，数值合理，无通信错误 |
| 3. 建立/核对零位 | 解除负载后建立或核对 Home | 机械零位、方向、V2 标定元数据一致 |
| 4. 单关节微动 | 低速、单轴、极小位移 | 方向、回读、软限位、停止均正确 |
| 5. 停止/关闭扭矩 | 发出停止并关闭扭矩 | 运动停止，扭矩状态确认关闭 |
| 6. 低速多关节 | 小范围、低速组合动作 | 无干涉，动态 raw 范围持续有效 |

每阶段开始前还应确认：工作区清空、机械臂固定、电源与接线正确、急停或断电手段在手、
第二人在场、预期移动方向已口头复核。不要从示例标定、旧动作或旧型号文件开始真机操作。

## 4. 记录要求

现场记录只写阶段结果、时间、操作者和经批准的设备标识；不要把串口、现场路径、
标定值、运行日志或其他机器特定值提交到仓库。真实标定和本地配置留在被忽略的本地文件，
另按现场备份流程保存。

只有六个阶段均由现场人员实际完成并留有记录，才能表述为“V2 真机验收通过”。
