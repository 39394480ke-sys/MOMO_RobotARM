# 开发板代码与现场数据同步设计

## 目标

让 GitHub 成为 MOMO 机械臂代码和默认模板的唯一基线，同时把真实标定、现场动作、姿态、本机参数保留在开发板，并自动同步备份到当前 Mac。完成后，开发板更新代码不应覆盖硬件真值，正常运行也不应持续产生 Git 工作区修改。

## 当前问题

- 开发板长期未更新远端索引，六个本地提交与 GitHub 中六个提交内容等价但提交编号不同。
- 更新远端索引后，GitHub 还有五个开发板未包含的有效提交。
- 开发板工作区同时包含新版代码、本机参数、真实标定、动作、姿态和运行数据，无法整体保留或整体丢弃。
- `标定文件.json`、姿态库和现场动作目前可能被 Git 跟踪；部分运行目录没有完整忽略。
- Mac 与开发板的视觉、运动和硬件参数存在差异，单层配置会持续制造工作区修改。
- 标定备份目前主要位于开发板同一存储设备，不能应对开发板存储损坏。

## 数据归属

### GitHub 管理

- Python、JavaScript、HTML、CSS 等程序代码。
- 默认配置和配置结构。
- `*.example` 标定、姿态和动作模板。
- 明确标注、不会直接作为现场动作运行的示例动作。
- 测试、文档、部署和备份脚本模板。

### 开发板本地管理

- 真实 `标定文件.json` 及历史标定备份。
- 现场保存的姿态库和录制动作。
- 摄像头索引、真实串口、视觉增益、关节方向和现场运动调参。
- AI 运镜项目等需要保留的现场创作数据。
- 运行状态、日志、最新画面、缓存、PID 和会话数据。

### Mac 备份管理

- 开发板重要现场数据的第二份副本。
- 每份快照的清单、生成时间和 SHA-256 校验值。
- 最近 30 天快照；清理只影响超期快照，不影响开发板当前数据。

## 配置模型

仓库继续保存现有默认配置，例如 `视觉配置.yaml`、`真实配置.yaml`、`Web配置.yaml` 和 `GUI配置.yaml`。同目录可放置被 Git 忽略的 `*.local.yaml`。

配置加载遵循以下顺序：

1. 读取仓库默认配置。
2. 如果同名本机覆盖文件存在，使用现有 `deep_merge` 进行递归合并。
3. 命令行或会话级覆盖最后应用。

开发板的 Pocket 3 `camera_index: 2`、视觉增益 `1.0`、`/dev/momo-servo` 和现场运动参数写入本机覆盖文件。Web/GUI 中会持久化的现场调参写入本机覆盖文件，不再改写仓库默认配置。

缺少本机覆盖文件时应保持当前默认行为。格式错误时应明确报告文件路径并拒绝静默使用部分配置。

## 模板与真实文件

- GitHub 保存 `真实舵机控制/标定文件.example.json`，不保存可直接代表某台机械臂零点的真实标定。
- 真实控制仍读取 `真实舵机控制/标定文件.json`。文件缺失时真实连接必须失败并提示执行标定，不得自动把示例标定当成真实标定。
- GitHub 保存姿态库和动作的结构示例；真实姿态库、现场动作目录和录制记录被忽略。
- 示例动作放在现有明确标注的示例目录中，不与现场动作扫描目录混用。

## 自动备份

### 写入前备份

标定、姿态和动作写入使用原子写入。在覆盖已有文件前，将上一版复制到对应历史目录。标定沿用现有时间戳备份机制，并增加统一的保留策略。

### 开发板每日快照

开发板脚本将以下内容复制到仓库外的 `/home/fibo/MOMO_RobotARM-local-backups/snapshots/<timestamp>/`：

- 本机覆盖配置。
- 真实标定和标定历史。
- 真实姿态库、现场动作和录制记录。
- AI 运镜现场项目。

快照不包含普通日志、PID、会话、缓存、最新摄像头画面和其他可再生文件。脚本生成 JSON 清单及每个文件的 SHA-256，并通过临时目录完成后原子改名。失败时保留上一个成功快照，返回非零状态。

开发板保留最近 30 天成功快照。清理前至少保留一个成功快照。

### Mac 定时拉取

Mac 使用 LaunchAgent 定时运行拉取脚本，通过现有 `BatchMode` SSH 和 `rsync` 从开发板读取成功快照，保存到 `~/MOMO_RobotARM-backups/qcs6490-odk/`。

任务在加载时运行一次，并每天运行。开发板或网络不可用时只记录错误，不删除 Mac 已有备份；下次运行继续同步。同步后验证清单中的 SHA-256，并清理 30 天前的 Mac 快照。

开发板不持有访问 Mac 的密钥或凭据。

## 首次迁移

1. 停止会写入动作、姿态或配置的操作；视觉预览可在快照完成后停止。
2. 在开发板仓库外创建完整迁移快照，并验证真实标定包含 J10-J15。
3. 为开发板当前 `HEAD` 创建带时间戳的只读备份分支；导出未提交补丁和未跟踪文件清单。
4. 识别与 GitHub 等价的代码，不把六个重复提交再次推送。
5. 以 `origin/main` 建立干净代码基线；旧分支和迁移快照均保留。
6. 把板端参数迁移到 `*.local.yaml`，把真实标定、姿态和动作恢复到忽略路径。
7. 安装开发板快照任务和 Mac LaunchAgent。
8. 验证 Git 工作区干净、配置合并结果正确、备份可恢复后再重启服务。

迁移过程不使用 `git reset --hard` 或对现场数据执行无备份覆盖。

## 验证与安全

- 单元测试覆盖配置深度合并、缺失覆盖文件、错误覆盖文件和本机配置写入目标。
- 测试 `.gitignore` 确实排除真实标定、现场动作、姿态和运行目录，同时保留模板。
- 快照测试覆盖清单、校验值、原子完成、失败保留和 30 天清理。
- Mac 拉取测试使用临时目录，验证离线不删除、重复同步幂等和校验失败报警。
- 开发板执行 Python 编译和相关现有测试。
- 视觉跟随先 dry-run，确认 Pocket 3、`camera_index: 2`、J11/J13、增益和方向。
- 舵机只做总线扫描、状态读取和 Home 预检；迁移验证不发送真实运动命令。
- 最终要求开发板 `main` 与 `origin/main` 对齐，常规运行后的 `git status` 保持干净。

## 回滚

任何阶段失败时停止继续迁移。代码可切回开发板迁移前备份分支，现场数据从仓库外完整快照恢复。本机覆盖文件、真实标定和动作数据恢复后，先执行配置检查和只读硬件检查，再恢复服务。
