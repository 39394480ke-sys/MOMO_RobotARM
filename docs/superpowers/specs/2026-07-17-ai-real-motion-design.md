# AI 对话真实运动设计

## 目标

让 Web 控制台中的 AI 对话可以把自然语言转换为受限的真实机械臂操作，同时保证模型不能直接驱动硬件。除停止类减险操作外，每个真实动作必须先显示规范化后的具体内容，再由用户二次确认后执行。

首期支持 J10-J15 关节运动、夹爪、回 Home、播放动作库动作以及启动或停止视觉跟随。GitHub 只保存默认关闭真实运动的配置模板；开发板通过本机覆盖配置启用真实工具，真实标定和现场数据继续留在开发板并自动备份到 Mac。

## 现状与问题

- `Agent配置.yaml` 当前设置 `allow_real_robot_tools: false`，因此模型可以生成工具调用，但真实模式会被安全策略拒绝。
- 现有桥接会自动填入安全确认文本，这不是真正由用户完成的逐动作确认；简单打开开关会让模型具备直接运动能力。
- Web 服务内嵌 Agent 时，除状态查询和停止外的工具会再次请求 `127.0.0.1:8010`，可能产生截图中的“机器人控制 API 不可用”误报。
- `rotate_joint.delta_deg` 把 J10 的毫米位移也描述成角度，容易造成界面、模型与真实动作单位不一致。
- AI 对话页目前只能显示文本回复，没有可验证、可取消、会过期的待确认动作。

## 总体架构

AI 工具调用分为“提议”和“执行”两个阶段：

1. 模型把自然语言转换成结构化工具参数。
2. 安全策略规范化参数，并读取实时状态计算目标值。
3. 对真实运动创建一条服务端待确认动作，不调用控制器。
4. Web 对话显示动作卡，包括当前值、变化量、目标值、单位、速度和持续性。
5. 用户点击“确认执行”或输入完整口令 `确认执行`。
6. 服务端根据动作 ID 取回冻结的参数，重新读取状态和执行第二次安全校验。
7. 校验通过后，直接调用同进程 `WebControlService`；模型不参与确认后的执行决策。

`stop_robot` 和 `stop_face_follow` 是减险操作，始终立即执行，并清除尚未确认的动作。其他真实运动均不得绕过待确认流程。

## 待确认动作

服务端内存中最多保存当前会话的一条待确认动作，字段包括：

- 不可猜测的动作 ID。
- 工具类型和规范化参数。
- 面向用户的动作摘要。
- 创建时间、30 秒过期时间和创建时的机器人状态快照。
- `pending`、`executed`、`cancelled`、`expired` 或 `invalidated` 状态。

新动作替换并取消旧动作。动作只能执行一次；服务重启、重置 AI 会话、切换控制模式、连接状态变化、急停或超时都会使其失效。

确认时重新读取相关关节。J10 与快照相差超过 `0.5 mm`，或旋转关节相差超过 `0.5°` 时拒绝执行，要求重新生成动作。相对运动以最新读数重新计算目标并再次校验；绝对运动保持冻结的目标值。确认按钮提交动作 ID，文本口令只确认当前会话唯一的待确认动作。普通的“确认”“好的”等表达不执行动作。

## 关节运动规则

关节工具改为单位明确的 `move_joint`，参数包含关节名、运动模式 `relative` 或 `absolute`，以及数值。模型工具说明明确 J10 使用毫米、J11-J15 使用角度。旧的 `rotate_joint` 仅保留兼容入口并在内部规范化，不作为新提示词的首选工具。

- J10 支持相对位移和绝对目标，最终目标必须位于 `-50 mm` 到 `50 mm`，单次位移不限。
- J11 支持相对旋转和绝对目标，最终目标必须位于 `-180°` 到 `180°`，单次旋转不限。
- J12-J15 只支持相对旋转，每条动作最大 `±3°`。AI 层不增加绝对角度范围，但底层控制器和硬件已有保护继续生效。
- 非有限数字、未知关节、错误单位、raw 舵机值和越界目标均在创建待确认动作前拒绝。
- 真实关节运动使用现有默认速度 `50%`；首期不让模型自由指定关节速度。

执行前若动作库播放或视觉跟随正在运行，新的关节运动、Home、夹爪或动作库播放请求被拒绝，提示用户先停止当前任务。

## 其他工具规则

### 夹爪

`set_gripper` 接受 `0` 到 `1` 的开合比例，动作卡同时显示比例和“打开/关闭/调整”描述。J16 未安装、未连接或未标定时明确拒绝，不返回伪成功。

### 回 Home

`run_robot_behavior(home)` 创建待确认动作前调用现有 Home 预检查。动作卡显示 Home 目标姿态和 `50%` 速度。确认时再次执行预检查，通过后回 Home。

### 动作库

`play_action` 只能选择服务端动作库中真实存在的动作。动作卡显示动作名、速度、帧数和可计算时长。AI 对话首期强制 `loop=false`，每次确认只播放一次；速度仍由现有动作播放服务校验。

### 视觉跟随

`start_face_follow` 使用开发板当前保存的视觉跟随配置。动作卡显示真实或 dry-run 模式、参与关节、单步上限和主要增益。真实模式确认后以 `dry_run=false` 启动并持续工作，直到用户停止或现有保护触发。`stop_face_follow` 无需确认并立即执行。

## Web API 与界面

`POST /api/v1/agent/ask` 的现有文本回复保持兼容，并可额外返回 `pending_action`。新增：

- `POST /api/v1/agent/pending/confirm`：提交动作 ID，执行当前待确认动作。
- `POST /api/v1/agent/pending/cancel`：提交动作 ID，取消动作。
- Agent 状态响应增加当前待确认动作及剩余有效时间，供页面刷新后恢复显示。

AI 工具桥接全部改为调用同进程服务方法，不再从 Web 服务内部 HTTP 回调自身。独立运行语音 Agent 时仍可保留 HTTP 桥接，但使用相同的安全策略，并且不得自动填入用户确认文本绕过待确认机制。

对话页在 AI 消息下显示一张紧凑的动作卡，提供“确认执行”和“取消”按钮，并显示待确认、执行中、成功、拒绝、取消或过期状态。按钮提交期间禁用，防止重复点击。执行结果回写聊天记录，并刷新机器人、会话、动作播放和视觉跟随状态。

## 配置与现场数据

仓库模板保持 `allow_real_robot_tools: false`。Agent 配置加载支持被 Git 忽略的本机覆盖文件；开发板覆盖配置将真实工具设为开启，Mac 和其他新部署默认仍为关闭。安全边界保存在仓库模板中，现场可以收紧但不能通过普通页面把边界放宽。

部署不覆盖开发板的真实标定、动作库、视觉参数或本机配置。更新前运行现有现场数据快照流程并把成功快照同步到当前 Mac，只同步明确的源代码和模板文件，不在脏工作区执行整体拉取、重置或检出。

## 错误处理

- 未连接真实机械臂、模式不符、动作过期、状态变化、并发任务、边界超限和硬件不可用均返回稳定错误码及可操作的中文说明。
- 模型提出非法动作时只得到拒绝原因，不能自行放宽规则或重复提交确认。
- 控制器执行失败时动作仍标记为已消费，不能使用同一动作 ID 重试；用户需要重新生成并确认。
- 停止操作尽力同时停止视觉跟随和当前运动，即使其中一项失败也继续尝试另一项并报告结果。

## 测试与验收

单元测试覆盖：

- J10 在 `-50/50 mm` 边界成功，越界失败，长距离单次运动在范围内成功。
- J11 在 `-180/180°` 边界成功，越界失败，大角度单次运动在范围内成功。
- J12-J15 的 `±3°` 成功，超过 `3°` 失败，绝对模式失败。
- 单位、非有限数字、raw 字段、未知关节和不可用夹爪被拒绝。
- 待确认动作的替换、取消、30 秒过期、重复确认、状态变化和模式切换失效。
- Home 双重预检查、动作不存在、动作只播放一次、视觉跟随真实启动和立即停止。
- Web 内嵌 Agent 不发起 localhost 自调用，独立 Agent 仍能使用受控 HTTP 桥接。

集成验证先在 dry-run 完成完整对话、动作卡、确认和取消流程。开发板部署后先断开舵机验证指令链，再连接真实机械臂低速测试停止、J12 `1°`、J10/J11 边界内动作、Home、单次动作库播放和视觉跟随。验收要求界面显示的单位、目标和执行结果与实时状态一致，任何真实增险动作都不能在缺少有效二次确认时执行。

## 回滚

关闭开发板本机覆盖配置中的真实工具开关即可立即恢复为只读 AI。源代码按部署前备份恢复；现场标定、动作和视觉配置不随代码回滚。若确认流程异常，保持真实工具关闭，只保留状态查询和停止操作。
