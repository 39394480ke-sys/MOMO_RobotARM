# 标定说明

标定把真实舵机 raw 位置映射为逻辑关节位置。开发板默认使用轻量
`scservo_sdk / feetech-servo-sdk` 路线；标定不是驱动库，也不是普通启动步骤。

## 文件边界

- 实际标定：`标定/current.local.json`，被 Git 忽略。
- V1 结构模板：`标定/v1.example.json`。
- V2 结构模板：`标定/v2.example.json`。

两个 example 文件都标有 `template: true`，只用于理解格式和测试，绝不能用于真机。
不要把串口、现场标定值、运行日志或机器绝对路径提交到仓库。

标定文件必须在 `_meta.robot_variant` 含准确型号。只有当前型号与该字段完全一致时
才允许进入真机路径；字段缺失、未知值或型号不匹配时，只能仿真或 `dry_run` 预览。
不能通过手工补写型号来复用未知来源的标定。动作文件的型号字段不同，是顶层
`robot_variant`，不要混淆两种结构。

## 配置来源

默认型号为 V2。配置按以下顺序加载：

1. 受版本控制的 `真实配置.yaml`
2. 被忽略的 `真实配置.local.yaml`
3. 由合并后 `robot.variant` 选中的权威型号 profile
4. 运行参数环境变量

默认 V2 由受控基线选择；临时型号写入被忽略的 `真实配置.local.yaml` 的
`robot.variant`。环境变量不提供型号选择，只覆盖串口、驱动后端和 `dry_run`。
受控默认必须保持串口为空且 `dry_run: true`。profile 的关节、传动、限位与 raw
可达关节等硬件字段优先于本地覆盖，不能被本地文件改写。

## V2 多圈关节

| 关节 | 机构 |
|---|---|
| J10 | 导轨，沿用既有机械与已核对的 V1 标定 |
| J11 | 底座旋转，1:5 |
| J12 | 肩部抬升，方向反向，1:28 |
| J13 | 肘部弯曲，1:13 |
| J14 | 腕部俯仰，直连 1:1 |
| J15 | 腕部旋转，直连 1:1 |

J10-J15 都按 signed absolute raw 处理，绝对上限为 `±30719`。V2 的
`raw_reachable_joints` 是 J12/J13：它们的有效逻辑范围必须依据当前
`home_present_raw`、传动映射和绝对 raw 上限动态计算。静态配置限位不能替代或放宽
这个范围，任何控制入口都不得绕过。

V2 重建标定时必须保留并复核 J10；如果旧标定缺少 J10，应在接触总线之前拒绝继续。
J11-J15 的 Home 必须在 CAD 定义的机械零位上建立。更换舵机、修改 ID/方向、拆装
结构或发现逻辑姿态与实物不一致时，都应重新走审批和标定流程。

## 真实操作审批

读取位置、关闭扭矩、写寄存器和运动是不同风险阶段，不能用一次批准覆盖全部操作。
每个实际硬件阶段必须单独明确批准，并按以下顺序执行：

1. ping
2. 只读 raw
3. 建立并核对零位
4. 单关节微小运动
5. 停止并关闭扭矩
6. 低速多关节运动

任何异常都应停止，不得跳级。写 `Operating_Mode`、`Homing_Offset`、`Phase` 或限位
寄存器属于单独的写操作，必须再次批准。完整现场清单见
[`../docs/V2真机验收.md`](../docs/V2真机验收.md)。

本轮文档更新没有连接、读取或驱动真实硬件。
